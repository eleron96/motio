# MCP-сервер

В Motio встроен сервер [Model Context Protocol](https://modelcontextprotocol.io):
ИИ-ассистент, который умеет работать с MCP, может читать одно пространство и
отвечать на вопросы о нём — кто занят на следующей неделе, что должно быть готово
по проекту, кто в отпуске в декабре.

Сервер только читает. Он не может ничего создать, сдвинуть или удалить и видит
одно пространство — то, которому принадлежит его токен.

Это [API пространства](api.md) в другой форме: тот же токен, те же данные, те же
правила.

## Подключение

1. Включите API и создайте токен с областью **Чтение пространства**, как описано в
   разделе [API пространства → Как включить](api.md#как-включить). Токен, который
   только импортирует отсутствия, не подойдёт.
2. Дайте ассистенту адрес и токен:

| | |
|---|---|
| Адрес | `https://<ваш адрес Motio>/functions/v1/mcp` |
| Транспорт | Streamable HTTP |
| Авторизация | заголовок `Authorization: Bearer motio_…` |

Тот же адрес показан в Motio: **Настройки рабочего пространства → API →
ИИ-ассистенты**.

Входа через OAuth сервер не предлагает: он принимает токен пространства и больше
ничего. Клиент, который умеет подключаться только через OAuth, пользоваться им не
сможет.

### Быстрый способ

В Motio откройте **Настройки рабочего пространства → API** и создайте токен с
правом **Чтение пространства**. В окне с новым токеном сразу показан готовый текст
для вашего ассистента — с вашим адресом и уже вставленным токеном: выберите
ассистента, скопируйте, вставьте. Рецепты ниже — тот же текст, но с адресом для
примера.

В каждом из них замените `planner.example.com` на адрес вашего Motio, а
`motio_YOUR_TOKEN` — на ваш токен.

### Claude Code

Вставьте в терминал:

```bash
claude mcp add --transport http motio https://planner.example.com/functions/v1/mcp --header "Authorization: Bearer motio_YOUR_TOKEN"
```

### Codex

Добавьте в файл `~/.codex/config.toml`:

```toml
[mcp_servers.motio]
url = "https://planner.example.com/functions/v1/mcp"
http_headers = { "Authorization" = "Bearer motio_YOUR_TOKEN" }
```

### Gemini CLI

Вставьте в терминал:

```bash
gemini mcp add --scope user --transport http --header "Authorization: Bearer motio_YOUR_TOKEN" motio https://planner.example.com/functions/v1/mcp
```

### Kimi Code

Добавьте в файл `~/.kimi-code/mcp.json` (если в нём уже есть другие серверы,
поставьте `motio` рядом с ними):

```json
{
  "mcpServers": {
    "motio": {
      "url": "https://planner.example.com/functions/v1/mcp",
      "headers": {
        "Authorization": "Bearer motio_YOUR_TOKEN"
      }
    }
  }
}
```

### Проверьте, что работает

Запустите ассистента и спросите: «К какому пространству Motio ты подключён?» Он
должен ответить названием вашего пространства.

### Другие ассистенты и токен вне файлов

Любому клиенту MCP нужны те же две вещи — адрес и заголовок — в его собственных
настройках. Рецепты выше кладут токен прямо в команду или файл настроек: так
проще всего, но команда ещё и остаётся в истории терминала. Чтобы держать токен в
переменной окружения, у каждого клиента свой способ: Claude Code подставляет
`${MOTIO_TOKEN}` в файле `.mcp.json` проекта, Codex принимает
`bearer_token_env_var = "MOTIO_TOKEN"`, Kimi Code —
`"bearerTokenEnvVar": "MOTIO_TOKEN"`.

Рецепты составлены по документации самих клиентов на ноябрь 2026 года. Само
подключение проверено с Claude Code и официальной клиентской библиотекой MCP; если
рецепт для другого клиента перестал работать, сверьтесь с его документацией.

## О чём может спросить ассистент

| Инструмент | Что возвращает |
|---|---|
| `get_workspace` | идентификатор и название пространства |
| `list_people` | все, кто есть на таймлайне: имя, почта и роль учётной записи, группа, активен ли человек |
| `list_projects` | проекты с кодом, статусом и клиентом; `archived` сужает список |
| `find_tasks` | задачи с фильтром по диапазону дат, проекту, человеку или «изменено после»; по умолчанию страница из 100 |
| `get_task` | одна задача с описанием и чек-листом |
| `list_milestones` | вехи, при необходимости — по диапазону дат или проекту |
| `list_time_off` | отсутствия, которые пересекаются с диапазоном дат |

Поля те же, что у соответствующих [методов API](api.md#чтение-пространства). Даты
— в виде `YYYY-MM-DD`; дата окончания задачи или отсутствия — её последний день,
включительно.

Что попробовать после подключения:

- «У кого нет задач на следующей неделе?»
- «Что должно быть готово по проекту Harbour bridge до конца месяца?»
- «Кто отсутствует в первой половине декабря и какие их задачи попадают на эти
  дни?»

## Ограничения

- 5 запросов в секунду с одного IP, всплеск до 20; сверх этого `429`.
- Запросы до 256 КБ.
- Без CORS и без запросов со страниц браузера: сервер рассчитан на ассистентов,
  которые работают на сервере или на вашем компьютере.

## Протокол

Для тех, кто пишет клиент. Адрес принимает только `POST`, по одному запросу или
уведомлению JSON-RPC за вызов, и отвечает одним объектом JSON; потоков он не
открывает и сессий не ведёт.

| | |
|---|---|
| Версии протокола | `2026-07-28`; для клиентов, которые начинают с `initialize`: `2025-11-25`, `2025-06-18`, `2025-03-26` |
| Методы | `server/discover`, `tools/list`, `tools/call`, `ping`; `initialize` для прежних версий |
| Возможности | `tools` |

Запрос версии `2026-07-28` несёт свою версию и возможности клиента в
`params._meta` и дублирует их в заголовках `MCP-Protocol-Version`, `Mcp-Method` и
(для `tools/call`) `Mcp-Name`; при несовпадении возвращается `400` и ошибка
JSON-RPC `-32020`. Ответы `server/discover` и `tools/list` несут подсказки
кэширования (`ttlMs` на час, `cacheScope: "public"`): инструменты одинаковы для
всех. Прежний клиент начинает с `initialize` и обслуживается той версией, которую
запросил; идентификатор сессии не выдаётся. Эти прежние версии не перечисляются ни
в `server/discover`, ни в ошибке «неподдерживаемая версия»: там названо только то,
чем может пользоваться запрос в новой форме.

Вне протокола сервер отвечает обычными статусами HTTP:

| HTTP | Когда |
|---|---|
| 401 | токен не указан, неправильного вида, неизвестен или отозван |
| 403 | у токена нет области `read` или запрос пришёл с заголовком `Origin` из браузера |
| 405 | любой метод, кроме `POST` |
| 413 | тело больше 256 КБ |
| 429 | лимит запросов; повторите через секунду |

Инструмент, который не может сделать то, о чём его просят, — неправильная дата,
неизвестный идентификатор задачи — отвечает с `isError: true` и сообщением, по
которому ассистент может исправиться.

## О безопасности

- Токен — это секрет: храните его в настройках ассистента или в переменной
  окружения и никогда — в репозитории. По токену на ассистента — и отзывать будет
  легко.
- Токен с областью `read` видит все задачи, описания и почты учётных записей
  пространства. Всё, что читает ассистент, может уйти ИИ-провайдеру, который за
  ним стоит: подключайте только тех ассистентов, которым вашей компании разрешено
  это передавать.
- Названия задач, описания и заметки — текст, написанный людьми из вашего
  пространства, и ассистент читает его как часть своего разговора. Корректный
  ассистент относится к нему как к данным; поскольку этот сервер ничего не может
  изменить, худшее, к чему здесь приведёт обманная заметка, — неверный ответ.
- Всегда подключайтесь по `https://` и держите токен в заголовке `Authorization`:
  токен в адресе оседает в журналах доступа.
- Создание и отзыв токена записываются в историю пространства (**Участники и
  доступ → История**).
- Запросы записываются в журнал сервера: название инструмента, пространство и
  короткий префикс токена (тот же, что показан в настройках), — так видно, какой
  ассистент спрашивал. Сам токен, почты, аргументы инструментов и заданные вопросы
  в журнал не попадают никогда.
