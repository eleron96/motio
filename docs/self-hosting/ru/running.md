# Повседневное

## Всё ли в порядке?

```bash
infra/scripts/install.sh status
```

Отчёт о состоянии, который ничего не меняет: версия и каталог с кодом,
контейнеры, отвечают ли шлюз API, вход, хранилище, бэкапы и Keycloak, свободное
место на диске, последний бэкап и вышел ли новый релиз. Приложите его, когда
просите о помощи.

Та же картина есть в браузере: войдите суперадмином и откройте **Админ-консоль →
Система** (`/app/admin/system`). Там видно:

- версию и новый релиз с точной командой обновления;
- отвечает ли каждый сервис;
- какие возможности и настройки сервера включены (только да или нет, без
  значений);
- кнопку **Отправить тестовое письмо** — для проверки [почты](./email.md);
- **Проверки входа**: открыта ли регистрация, подтверждение адреса, почта
  Keycloak, а для каждого внешнего провайдера входа — Trust Email, Sync mode и
  мапперы групп, с указанием, что требует внимания (например, Trust Email
  выключен, а адреса нужно подтверждать);
- **Отчёт для поддержки**: один файл с версиями, переключателями, состоянием
  сервисов, настройкой входа и счётчиками — без имён, адресов и секретов.
  Приложите его к сообщению об ошибке.

Раздел только читает: обновление остаётся командой `install.sh update` на
сервере.

## Другие инструменты админ-консоли

- **Админ-консоль → Журнал** (`/app/admin/activity`): что суперадмины меняли в
  консоли (настройки, участники и роли, пространства, соответствия групп,
  рассылки, объявления) и что синхронизация групп сделала сама — кто пришёл через
  группу, кого убрали, чья роль последовала за группой. Настройки, изменённые
  через `install.sh settings`, тоже там. У бэкапов и у консоли самого Keycloak
  свои журналы.
- **Админ-консоль → Пользователи → Подробнее**: пространства человека и то, как
  он входит, — учётная запись Keycloak (включена или нет, подтверждён ли адрес,
  что Keycloak спросит при следующем входе), провайдеры, с которыми она связана,
  её группы Keycloak, откуда берётся роль суперадмина и что синхронизация групп
  сделает при его следующем визите. Просмотр ничего не меняет.
- **Админ-консоль → Приглашения** (`/app/admin/invitations`): все приглашения, на
  которые никто не ответил, во всех пространствах, с кнопками **Скопировать
  ссылку** (полезно без почты) и **Отозвать**.

## Логи и контейнеры

`infra/scripts/selfhost-compose.sh` — это `docker compose` с нужными файлами и
`.env` этой установки:

```bash
infra/scripts/selfhost-compose.sh ps
infra/scripts/selfhost-compose.sh logs -f --tail=100
infra/scripts/selfhost-compose.sh logs --since 15m functions
infra/scripts/selfhost-compose.sh restart functions
```

Сервисы — чтобы знать, чей лог читать:

| Сервис | Что делает |
|---|---|
| `web` | веб-приложение (статические файлы) |
| `caddy` | HTTPS и маршрутизация; единственный контейнер, доступный снаружи |
| `gateway` | шлюз API перед серверными сервисами |
| `auth` | сессии (GoTrue) |
| `rest` | API данных (PostgREST) |
| `realtime` | живые обновления |
| `storage` | загруженные файлы |
| `functions` | серверные функции: админ-консоль, почта, push, синхронизация групп, API |
| `db` | PostgreSQL |
| `keycloak`, `keycloak-db` | учётные записи и вход, и их база |
| `oauth2-proxy` | проводит любой другой путь через вход Keycloak |
| `backup` | ночные бэкапы и задачи по расписанию |

> [!TIP]
> Перезапустив по отдельности `auth`, `rest`, `realtime` или `backup`,
> перезапустите и `gateway`: он узнаёт их адреса только при старте.
> `install.sh up` делает всё это в правильном порядке.

## Portainer, WUD и Beszel

Motio уживается с этими инструментами, но кое-что стоит знать.

**Portainer.** Ставьте и обновляйте Motio командой `install.sh` по SSH, а не как
стек Portainer: обновление ещё и мигрирует базу и снимает полную копию, а стек —
это несколько файлов compose плюс созданные установщиком настройки. Portainer
показывает стек `motio` как созданный вне Portainer (ограниченное управление).
Логи, консоль, статистика, запуск, остановка и перезапуск там работают. Не
разворачивайте стек заново и не правьте его из Portainer: меняйте настройки в
`.env` и выполняйте `install.sh up`.

**What's Up Docker (WUD).** Образы Motio подобраны и проверены вместе и меняются
только с релизом Motio ([Безопасность](./security.md)). WUD будет сообщать о новых
версиях образов вроде `supabase/postgres` или `keycloak`: не применяйте их по
одному, обновляйте Motio. Сам Motio собирается на вашем сервере, поэтому его
релизов WUD не видит. Чтобы WUD молчал о контейнерах Motio, пометьте их в файле
своих дополнений ([ниже](#свои-дополнения)):

```yaml
x-no-wud: &no-wud
  labels:
    wud.watch: "false"

services:
  db: *no-wud
  keycloak-db: *no-wud
  keycloak: *no-wud
  auth: *no-wud
  rest: *no-wud
  realtime: *no-wud
  functions: *no-wud
  storage: *no-wud
  gateway: *no-wud
  backup: *no-wud
  web: *no-wud
  oauth2-proxy: *no-wud
  caddy: *no-wud
```

**Beszel** и любому другому монитору контейнеров от Motio ничего не нужно.
Контейнеры называются `motio-<сервис>-1`, и у каждого есть лимит памяти,
рассчитанный на сервер с 4 ГБ.

## Сети

Стек работает в собственной сети Docker — `motio_default`. Никто другой к ней не
подключается, а снаружи доступен только Caddy:

- на портах 80 и 443 (режим `tls`);
- на `127.0.0.1:<--http-port>` (режим `proxy`);
- либо только через сеть вашего прокси (`--proxy-network`).

Шлюз API и Keycloak тоже слушают порты на `127.0.0.1` (`--gateway-port`,
`--keycloak-port`): ими `install.sh` пользуется при настройке и в `status`.

## Свои дополнения

Файл `infra/docker-compose.selfhost.local.yml`, если он есть, накладывается поверх
файлов compose Motio командами `install.sh` и `selfhost-compose.sh`: метки,
дополнительная сеть, другие лимиты памяти. Он не входит в репозиторий, поэтому
обновления его не трогают. Пути в нём задаются относительно каталога `infra/`.

Ограничьтесь дополнениями: менять в нём сервисы, тома или порты самого Motio не
поддерживается.

## Удаление

```bash
infra/scripts/selfhost-compose.sh down -v   # -v удаляет и все тома с данными
```

Бэкапы в `infra/backups/` остаются, пока вы не удалите каталог.
