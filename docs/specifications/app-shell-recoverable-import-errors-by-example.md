# App Shell Recoverable Import Errors — Behavior by Example

Этот документ фиксирует ожидаемое поведение frontend shell при ошибках
ленивой загрузки чанков после релиза.

## Сценарий: пользователь открывает stale build после деплоя

- Допустим, пользователь держит вкладку Motio открытой во время деплоя.
- И entry chunk уже загружен из предыдущего релиза.
- И при переходе на lazy route браузер получает ошибку вида
  `Failed to fetch dynamically imported module`.

Ожидаемое поведение:

- приложение должно считать такую ошибку recoverable;
- приложение должно выполнить один hard reload в рамках текущей вкладки;
- после перезагрузки браузер должен запросить свежий `index.html`
  и актуальные asset hashes;
- пользователь не должен вручную чистить cache, чтобы продолжить работу.

## Сценарий: reload не решил проблему

- Допустим, после hard reload та же ошибка импорта для того же чанка
  повторилась снова в этой же вкладке.

Ожидаемое поведение:

- приложение не должно входить в бесконечный reload loop;
- error boundary должен показать безопасный fallback без технического URL;
- пользователь должен иметь возможность вручную повторить reload
  через кнопку восстановления.

## Сценарий: обычная render error

- Допустим, ошибка не связана с динамическим импортом чанка.

Ожидаемое поведение:

- приложение не должно делать hard reload автоматически;
- error boundary должен работать как обычный recovery fallback;
- кнопка `Try again` должна заново отрендерить subtree без принудительной
  перезагрузки страницы.
