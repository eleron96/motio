# Установка

## Получите код

```bash
git clone https://github.com/eleron96/motio.git
cd motio
git checkout vX.Y.Z           # тег последнего релиза со страницы Releases
```

Ставьте с тега релиза, а не из `main`: теги — это версии, которые выпущены и
проверены для своих серверов.

## Выберите режим

### `tls`: сервер доступен из интернета напрямую

Caddy в составе Motio занимает порты 80 и 443 и получает сертификат Let's Encrypt.

```bash
infra/scripts/install.sh --domain planner.example.com --email you@example.com
```

### `proxy`: у вас уже есть обратный прокси

Nginx Proxy Manager, Traefik, nginx, HAProxy… Motio слушает обычный HTTP только
на `127.0.0.1`, а TLS завершает ваш прокси.

```bash
infra/scripts/install.sh --domain planner.example.com --email you@example.com \
  --mode proxy --http-port 8088
```

В прокси создайте **один** хост для `planner.example.com`, который пересылает всё
на `http://127.0.0.1:8088`. Больше ничего настраивать не нужно: пути разводит
Caddy в составе Motio, стоящий за прокси. Примеры: [Обратный прокси](./reverse-proxy.md).

### `proxy` через общую сеть Docker

Если ваш прокси работает в Docker и ходит к приложениям по общей сети (Nginx
Proxy Manager с `npm_backend`, Traefik со своей сетью…), подключите Motio к этой
сети вместо публикации порта:

```bash
infra/scripts/install.sh --domain planner.example.com --email you@example.com \
  --mode proxy --proxy-network npm_backend
```

К сети подключается только Caddy из Motio, под именем `motio` (это имя из
`--instance`), и прокси пересылает на `http://motio:80`. Сеть должна существовать
до установки (`docker network ls`). На уже работающей установке задайте
`MOTIO_PROXY_NETWORK=npm_backend` в `.env` и выполните `install.sh up`.

## Все параметры установки

| Параметр | Что делает |
|---|---|
| `--domain HOST` | Ваш адрес, например `planner.example.com`. Обязателен. |
| `--email EMAIL` | Ваша почта: контакт для Let's Encrypt и отправитель писем. Обязателен. |
| `--mode tls\|proxy` | См. выше. По умолчанию `tls`. |
| `--http-port PORT` | Локальный порт для `--mode proxy`. По умолчанию `8088`. |
| `--proxy-network NAME` | Подключиться к сети Docker вашего прокси вместо публикации порта. |
| `--public-url URL` | Публичный адрес, если он не `https://<домен>` (например, прокси на другом порту). |
| `--version TAG` | Какой релиз ставить; по умолчанию — тот, что сейчас в каталоге. |
| `--instance NAME` | Имя проекта compose и приставка томов. По умолчанию `motio`. Двум установкам на одном сервере нужны два разных имени. |
| `--gateway-port`, `--keycloak-port` | Локальные порты шлюза API и Keycloak. По умолчанию `8080`, `8081`. |
| `--smtp-host`, `--smtp-port`, `--smtp-user`, `--smtp-pass`, `--smtp-from` | Исходящая почта; см. [Почту](./email.md). |
| `--env-only` | Только записать `.env` и остановиться, чтобы сначала его просмотреть; затем всё запускает `install.sh up`. |

## Что делает установщик

1. Проверяет Docker, Compose, память и программы из [Требований](./requirements.md).
2. Пишет `.env` (права `600`): случайные пароли, секрет JWT и подписанные ключи
   API, секрет клиента Keycloak, ключи Web Push и все публичные адреса, выведенные
   из вашего домена. Существующий `.env` никогда не перезаписывается, так что
   повторный запуск безопасен.
3. Запускает базу, Keycloak и серверную часть, применяет настройки Keycloak,
   выполняет миграции базы, создаёт резервную учётную запись администратора,
   собирает веб-приложение и запускает Caddy.
4. Печатает адрес и подсказывает, где искать пароли администраторов.

Первый запуск занимает 10–15 минут, большая часть — сборка веб-приложения.

> [!NOTE]
> Первая миграция печатает несколько замечаний об объектах, которых ещё нет, среди
> них `realtime.messages not found, task draft channel policies skipped`. Это
> ожидаемо: сервис realtime создаёт таблицу, когда подключается первый браузер, а
> правила добавит следующий `install.sh up` или `update`. Они нужны только для
> живых черновиков в задачах, которые по умолчанию выключены.

## Вход

Откройте ваш адрес и выберите **Создать аккаунт**: зарегистрируйтесь со своей
почтой. Вы получите своё пространство и пригласите в него команду из настроек
(**Настройки рабочего пространства → Участники и доступ**; подробнее — в разделе
[Люди и пространства](./people.md)).

Для администрирования есть ещё две учётные записи:

| | Где | Логин |
|---|---|---|
| Резервный админ (суперадмин) | `https://<домен>/app/admin` | `RESERVE_ADMIN_EMAIL` / `RESERVE_ADMIN_PASSWORD` из `.env` |
| Администратор Keycloak | `https://<домен>/admin` | `admin` / `KEYCLOAK_ADMIN_PASSWORD` из `.env` |

Резервный админ — служебная учётная запись для админ-консоли, а не для работы в
Motio. Как открыть админ-консоль себе, см. в разделе [Администраторы](./admins.md).

## Закрыть регистрацию (по желанию)

Регистрация открыта всем, кто может открыть ваш адрес. Когда у команды уже есть
учётные записи или люди приходят через ваш собственный вход, её можно закрыть:
Keycloak → realm **timeline** → **Realm settings** → **Login** →
**User registration** выключить. После этого люди попадают в Motio по приглашению,
напрямую от суперадмина или по своим группам; см. [Люди и пространства](./people.md).

Обновления никогда не включают регистрацию обратно.

Дальше: [Администраторы](./admins.md) или [Обратный прокси](./reverse-proxy.md),
если вы выбрали `proxy`.
